# AutoTap 1.0.3 手势显示与桌面快捷操作更新

基于 1.0.3 后台/锁屏修复源码继续更新，不包含新版越狱巨魔适配。应用版本、内部构建号和 ZIP 名称保持 1.0.3。按要求移除 1.0.4 源码。

## 本次更新

- 桌面快捷操作响应修复：显式声明场景生命周期，使用 SwiftUI 支持的场景代理配置；冷启动请求从连接选项接收，后台请求从场景快捷操作回调接收。
- 快捷请求保留到页面已就绪、场景已激活且设备已解锁时，再交给原有模式入口；激活或受保护数据恢复会再次处理待执行请求，不再只尝试一次或依赖旧的应用级激活回调。
- 快捷入口仍然只打开悬浮窗待命或独立脚本列表，不自动点击、录制或回放；本次未修改触摸发送、录制与锁屏暂停核心代码。
- 手势录制中的点击在原生悬浮层增量显示数字标记；滑动不再被伪装成点击目标。
- 录制滑动时显示跟随手指的轨迹与触点，抬手后保留该条轨迹。视觉层不参与命中测试，不改变真实触摸发送链路。
- 打开已保存的手势脚本时显示点击数字与滑动轨迹；数字对应原始动作顺序，例如点击、滑动、点击时显示 1、3。
- 待命或暂停时显示静态轨迹预览，回放时仅动画显示当前滑动。旧版只有起终点的手势脚本同样支持轨迹预览。
- 修复首次创建悬浮窗前缓存空轨迹的问题，并在屏幕旋转后重投影轨迹。
- 新增桌面长按 AutoTap 的四个快捷菜单：单点、多点、录制脚本、手势脚本。单点、多点仅打开悬浮窗待命；录制和手势快捷项打开各自独立脚本列表，不自动执行。

## 后台与锁屏

- HID 监听、注册与销毁改用独立输入线程，不再将同步系统过滤器挂在 UIKit 主线程。
- 锁屏通知立即关闭原生输入门；监听撤销、最终抬手和发送客户端清理由后台队列完成，不同步等待主线程或触摸发送锁。
- 已发送的按下事件必须对应抬手；取消发送时不再提前丢弃“仍有手指按下”的状态。
- 锁屏时悬浮窗停止命中测试，延迟重绘、托管重试及完成提示不再提交图层。
- 解锁通知不自动重新执行。只有回到已解锁的 AutoTap 前台才恢复悬浮窗交互，脚本仍保持暂停，需要手动继续。
- 音频中断或后台保活失效时安全暂停输入。后台音频停止前先等待已排队的输入清理，避免留下受系统调用的过滤器。
- 主线程无法及时处理输入时，过滤器放行系统触摸；关闭/重开时旧会话排队事件失效。
- 触摸硬件流限制为最多 240 帧/秒，减少极短间隔造成的 BackBoard 事件积压。1 毫秒等设置仍可保存，但实际触摸速度不是实时保证，最快约 120 次点击/秒。

## 未改动

两份安装权限文件与原 1.0.3 完全一致，安装范围不扩展。四个模式的脚本状态、列表与执行顺序保持独立；触摸注入、后台保活、首页布局、启动页和图标未改动。锁屏入口不绘制或移除新增轨迹层，解锁回到前台后再清理实时触点。

## 验证边界

在 Windows 工具链上检查 arm64 Objective-C 编译、全部 Swift 的 iOS 15 类型检查、工程/资源/版本与源码 ZIP 一致性。此环境无法运行 SpringBoard、实际 IOHID 私有接口，也没有连接真机；因此不能用编译成功替代后台锁屏真机结果。

发布 IPA 前请按 `VALIDATION.md` 完成真机验收。此源码包不是已验证的 IPA，未自动上传 GitHub。
