# AutoTap · iOS 15+ · TrollStore 跨进程版

当前重新迭代基线版本：**1.0**。

AutoTap 是一个面向 TrollStore 环境的 iPhone、iPad 自动点击工具。工程使用 SwiftUI + UIKit，最低部署版本为 iOS 15.0，不依赖第三方包，并为 iOSForge 的无证书 IPA 构建准备了共享 Scheme 与 `iosforge.toml`。

> **构建类型必须选择 `.ipa iOS 应用`，不要选择 `dylib`。** 本项目是完整的 Xcode App 工程，不是 Theos 动态库工程。工程应识别为 `AutoTap.xcodeproj`，共享 Scheme 为 `AutoTap`。

## 已实现

- 单点击：只循环执行当前选中的点击目标。
- 多点击：按编号依次执行多个点击或滑动动作。
- 可视化坐标编辑器：点击添加目标，拖动目标调整位置；坐标以 0...1 的比例保存，适配不同屏幕尺寸。
- 动作参数：每个编号可独立设置点击间隔、按压时长、滑动时长、单动作重复次数；间隔单位支持毫秒（默认）、秒、分钟。
- 运行参数：启动倒计时、循环次数、多点/录制脚本每轮完成后的等待秒数；不设置最长运行时间，任务只在达到循环条件或手动暂停/停止时结束；每个编号的间隔、时长和重复次数独立保存。
- 脚本管理：新建、复制、重命名、删除、JSON 导入与导出。
- 系统托管悬浮窗：采用独立可视窗口和交互窗口，调用 `SBSAccessibilityWindowHostingController` 注册到系统，可在切换到目标 App 后继续显示。
- 悬浮控制条：单点、多点互斥开启；支持开始、暂停/继续、添加、从末尾删除、设置和稳定拖动。运行时编号层不拦截合成点击。
- 编号直接交互：暂停或待机时可直接拖动任意编号；轻点编号会在悬浮层打开该编号的独立参数面板，可用内置数字键盘手动填写间隔、单位、按压时长和重复次数。
- 启动倒计时：倒计时会以悬浮圆形提示显示在目标 App 上；设为 0 秒可立即开始。
- v10 原始触摸直控：后台 UIKit 不再负责悬浮控件手势。HID 监听器直接解析实体手指的按下、移动和抬起，并直接移动数字容器或控制条、触发按钮，切换 App 后仍可暂停和拖动。
- v10 单一数字容器：编号的可见内容与拖动热区是同一个视图；拖动过程中只移动该容器且不重建悬浮层，抬手后才保存归一化坐标，避免旧位置残影。
- v11 单一输入链路：移除悬浮层残留的 UIKit 点击与拖动监听，所有悬浮控件只由原始 HID 触摸驱动，避免一次点击触发两次而导致“刚启动又暂停”或重复打开设置。
- v11 设置切换：从悬浮条进入设置时先暂时隐藏托管 HUD，待 AutoTap 真正进入前台后再打开编辑页；关闭编辑页会自动恢复悬浮层，不再遮住主界面造成假死。
- v11 精简编辑页：单点和多点设置移除横竖屏选择及目标位置画布，目标位置统一直接在悬浮层拖动调整。
- v12 设置上下文复用：进入 AutoTap 设置时只临时隐藏并禁用现有 HUD，不再销毁和重建 WindowServer 托管上下文，返回后恢复同一个窗口，避免旧位置残留第二个数字。
- v12 首次点击预热：每次开始任务前重新创建 HID 发送客户端，并发送一个不接触屏幕的中性数字化帧，防止第一次真实点击被系统初始化过程吞掉。
- v12 暂停编辑刷新：暂停后只要拖动编号或修改参数，下一次播放会从最新配置重新启动，不再继续使用首次启动时保存的旧坐标快照。
- v13 触摸隔离：悬浮层注册 HID 过滤回调；从数字或控制条开始的按压会被悬浮层独占，拖动时不会再带动底下 App 的滚动。
- v13 坐标统一：悬浮层继续使用屏幕比例保存位置，发送层转换为系统级 HID 接受的 0...1 显示坐标。
- v14 点击回归修复：HID 过滤器在同步发送期间及时间戳命中时跳过本程序生成的事件，避免悬浮层把自动点击本身拦截掉；同时恢复系统级数字化事件需要的归一化坐标。
- v14 常亮与锁屏：运行时屏幕常亮会同时启用 UIKit 空闲计时器和后台电源管理断言；手动锁屏或系统强制熄屏时通过多路锁屏通知立即暂停并释放触点。
- v14 设置返回残影：进入通用设置时不再隐藏或重建已托管的 UIWindow，只把原有根图层透明化并禁用交互，返回后复用同一个上下文和同一组数字视图。
- v16 启动动画恢复：按早期版本恢复为纯色系统启动背景，随后由同一个 SwiftUI 组合视图一次性显示白底点击图标与 AutoTap 名称；不再用系统启动页分别绘制图标和文字。
- v15 暂停死锁修复：HID 发送在取得主线程窗口上下文后才进入发送锁，避免自动点击线程与主线程暂停操作相互等待；托管窗口暂时无法返回 UIKit 命中结果时，控制条会使用屏幕几何兜底识别暂停按钮。
- v17 单一启动品牌图：图标与 AutoTap 名称合成为同一个浅色/深色资源，系统 LaunchScreen 与应用启动遮罩使用相同图片、相同固定尺寸和相同中心点，并将应用内展示延长到 1.1 秒，避免看不到或先后分离。
- v17 重开位置稳定：悬浮 HUD 明确禁止成为 Key Window，并在显示和关闭时保留应用自己的主窗口，避免重复开启后 SwiftUI 安全区重算导致整个页面向下偏移。
- v18 启动空白修复：移除真机启动阶段无法解析的合成图片引用，系统启动页与 SwiftUI 遮罩重新使用已验证的 TapLogo；图标和名称放进同一个 220×145 固定组合容器，间距固定为 6 点并同步适配深色文字。
- v19 多点顺序修复：单点与多点不再共用“执行次数 0”的含义；单点 0 仍表示当前点无限执行，多点 0 表示每轮该编号执行 1 次并严格按 1 → 2 → 3 → … 循环，避免目标 1 独占任务。
- v19 重开删除修复：每次悬浮层显示都生成新的注册代次，关闭后旧的延迟注册回调立即失效；托管命中失灵时还会逐个解析控制条按钮，避免重新开启后减号偶发无响应。
- v19 录制模式：悬浮层监听控制条外的真实手动轻点，按发生顺序、点位、点击间隔和按压时长生成多点脚本；红色停止键结束录制，返回 AutoTap 输入脚本名称后保存，可继续逐点修改并直接回放。
- v20 录制入口与脚本库：首页录制模式恢复为和单点/多点相同的“设置 + 开启/关闭”结构；开启只显示悬浮条，切换到任意 App 后点红色录制键才开始捕获。设置页会列出旧版及新版保存的录制/多点脚本，可编辑每个点、删除脚本或直接启动脚本悬浮层。
- v20 轮次等待：多点和录制脚本增加“每轮完成后间隔”，整轮最后一个编号结束后按设置等待，再从编号 1 开始下一轮；0 表示立即进入下一轮，不会再叠加最后一个编号自身的点击间隔。
- v20 启动品牌可见性：恢复早期版本的 108 点图标、16 点间距和 AutoTap 名称组合，应用内启动遮罩至少显示 1.8 秒；同时换用新 LaunchScreenV20 名称规避旧安装的启动快照缓存。
- v20 通用设置精简：移除目标应用与 Bundle ID，单点、多点和录制均通过悬浮层在当前前台 App 操作。
- v21 暂停恢复加固：悬浮按钮统一去除 UIKit 与原始 HID 的重复回调；暂停会使正在进行的旧触摸链立即失效，恢复前重新创建并预热 HID 客户端，再从完整的 DOWN 事件重试被中断动作。单点、多点和录制回放共用这套状态机。
- v21 脚本彻底分仓：单点、多点、录制分别维护脚本列表和各自最后选中的脚本，切换模式不再改写另一个模式的 `mode`。运行中的悬浮层还会锁定自己的脚本 ID，其他页面的选择不会换掉当前点位。
- v21 旧数据修复：升级时会按类别校正脚本模式；包含多个目标却被旧版错误保存成单点的脚本会恢复为多点，避免只重复执行编号 1。
- v22 录制按钮闪退修复：修正录制状态 Objective-C setter 对自身的无限递归，并将悬浮条重建推迟到当前触摸释放后的下一轮主线程，点红色录制按钮不再关闭悬浮窗或触发栈溢出。
- v22 启动品牌重制：重新生成浅色/深色两套完全不透明的“图标 + AutoTap”整体位图，系统启动页和应用内遮罩统一使用同一品牌资源，并换用 `LaunchScreenV22` 避免旧启动快照缓存。
- v22 首页自适应：主页去掉纵向滚动依赖，手机竖屏使用紧凑单列，手机横屏与 iPad 自动使用三栏；标题固定左对齐，并按可用高度隐藏次要说明和版本脚注，主要功能保持在一个界面内。
- v23 录制脚本交互：录制回放悬浮层不再显示加减键，保存后的编号在前台/后台均锁定；从脚本设置点“按编号顺序执行”可进入专用画布拖动修改位置。
- v23 暂停策略：每个录制脚本可单独选择“从暂停位置继续”或“暂停后从编号 1 重新开始”，不会影响单点、多点及其他录制脚本。
- v23 完成提示与遮挡优化：录制脚本达到设定循环次数后在跨进程悬浮层显示完成提示；任一模式运行或录制时，编号标记降为 20% 不透明度，暂停后恢复。
- v23 启动与布局：启动页改用直接打包的浅色/深色不透明 PNG，并保留代码兜底的图标与名称；普通 iPhone 不再误用过度缩小布局，版本号始终可见且可点按检查 GitHub 更新。
- v23 数据目录：移除禁止系统数据容器的 entitlement，配置与录制脚本写入应用数据目录，并在首次升级时尝试迁移旧的全局配置文件。
- 当前脚本持久化：脚本保存改为主文件与备份文件双写，读取失败时自动尝试备份；保存失败会明确提示，不再静默丢失录制结果。
- 当前导入导出：单点、多点、录制三类脚本各自支持 JSON 导入与导出；导出文件直接出现在“文件 > 我的 iPhone > AutoTap”，导入默认打开该目录并可继续浏览其他位置。
- 当前悬浮外观：控制条、编号标记、倒计时和完成提示跟随系统浅色/深色模式，浅色使用白底，深色使用黑底。
- 当前设置精简：移除时间浮动、位置浮动及执行层随机偏移逻辑；首页完成记录可一键清空。
- 跨应用执行：通过私有 IOKit HID 接口向前台应用发送触摸，并用后台音频维持悬浮窗响应和任务执行。
- v8 后台保活：使用循环的非零低振幅 PCM 播放和系统后台任务桥接；启动任务前的内部重置不再误停保活，避免切换到桌面后倒计时停在原值。
- 无限执行：单点模式的“连续执行次数”填 0 时持续执行当前点；多点模式填 0 时该编号每轮执行 1 次，由整个编号序列持续循环，直到用户手动暂停或停止。
- 锁屏保护：收到系统锁屏事件时自动暂停并释放当前触点；若系统仍强制终止进程，下次启动会提示上次任务已中断，不会自动继续误触。
- 安全提示：间隔和按压时长可填写 1 ms，但低于约 40 ms 时系统计时精度可能导致实际间隔略有偏差。

## 重要限制

普通签名的 iOS 应用没有 Android `AccessibilityService` 对应的公开接口。本工程使用和 TrollStore 系统工具同类的私有窗口托管与 HID 权限，因此：

- 首页点击“开启”会先显示当前模式的悬浮控制层；点击控制层播放键后才开始执行。
- 跨应用悬浮窗和点击只面向你拥有并获授权的 TrollStore / 越狱设备；它不能上架 App Store。
- 必须用 TrollStore 安装并保留源码内嵌的私有 entitlements。普通 Apple 证书、免费自签、侧载工具通常会删除或拒绝这些权限，届时跨进程悬浮窗与 HID 点击不会工作。
- 工程按系统分辨率动态计算窗口与比例坐标，支持 iOS / iPadOS 15+ 的 iPhone、iPad 与横竖屏；私有接口仍可能随系统版本变化，必须以真机测试为准。
- 请先用较长间隔和短运行时长测试。不要在支付、身份验证、删除数据等高风险界面使用。

## 用 iOSForge 编译

1. 按 iOSForge 使用指南建立你自己的私有构建仓库，并放入官方初始化包。
2. 在 iOSForge 工作台选择 `.ipa iOS 应用` → `上传本地源码`。
3. 上传本目录或交付 ZIP；不要解散 `AutoTap.xcodeproj` 目录。
4. 选择“无证书编译”。单工程可留空自动识别；手动填写时使用：
   - 工程：`AutoTap.xcodeproj`
   - Scheme：`AutoTap`
   - Configuration：`Release`
5. 下载 IPA。工程在无证书构建阶段优先使用 `ldid` 写入 `AutoTap/AutoTap.entitlements`；若云端 Runner 没有安装 `ldid`，会自动改用 macOS 自带的 `/usr/bin/codesign` 进行临时签名并嵌入同一份权限。完成后请直接交给 TrollStore 安装。

> 不要再用普通自签覆盖该 IPA；重新签名可能清除跨进程悬浮窗和 HID 权限。

## TrollStore / 私有权限

仓库根目录提供 `entitlements.plist`，Xcode 工程引用 `AutoTap/AutoTap.entitlements`。两份内容一致，包含 WindowServer、QuartzCore 显示上下文、SpringBoard 无障碍窗口托管、BackBoard 和 HID 所需权限。工程末尾的构建阶段只在 `CODE_SIGNING_ALLOWED=NO` 的真机构建中执行，并兼容已安装 `ldid` 和仅提供系统 `codesign` 的 GitHub macOS Runner。

## 使用

1. 在首页开启“单点模式”或“多点模式”，悬浮目标默认出现在屏幕中央。
2. 直接拖动悬浮编号调整目标位置；多点模式使用加号添加目标、减号从最后一个目标开始删除，并严格按 1 → 2 → 3 → … 顺序执行。
3. 轻点任意悬浮编号，独立填写它的间隔（毫秒 / 秒 / 分钟）、时长和重复次数；单点模式使用同一套参数。
4. 点击悬浮控制条的播放键即可在当前前台 App 开始，启动倒计时会显示在悬浮层。
5. 运行时点击橙色暂停键可暂停，再点蓝色播放键继续；白色关闭键会停止执行并关闭当前模式悬浮窗。
6. 录制模式点击“开启”只显示悬浮条；切换到目标 App 后点红色录制键，再正常轻点。拖动和滑动不会被记成点击；点红色停止键返回 AutoTap 命名保存。保存后的录制点在悬浮层锁定，进入该脚本设置并点击“按编号顺序执行”可在画布中拖动修改。
7. 录制脚本的“每轮完成后间隔”只作用在整轮最后一个编号与下一轮编号 1 之间；0 表示立即开始下一轮。
8. 三种模式都可从脚本设置中导入或导出 JSON；导出文件位于“文件 > 我的 iPhone > AutoTap”，导入器会默认打开该目录，也可浏览其他文件夹。
9. 点击首页状态卡右侧“清空”可清除已执行次数和累计时间；点击底部版本号会检查 `mango6i/iOS-AutoTap` 的最新 GitHub Release。
