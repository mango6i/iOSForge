先了解：这个网页帮你做什么？

你把已有的项目源码放到 GitHub，再回到工作台选择要生成的文件。GitHub 会启动一台云端 Mac，按照项目的编译规则，把源码变成可以下载的产物。你使用 Windows 电脑也可以操作。

第一次使用，先确认自己有没有源码。

源码是包含代码和编译配置的完整工程。只有一个现成的 IPA、dylib 或 deb，不是源码；更改文件后缀也不能把它变成另一种格式。当前网页负责发起构建，不提供源码上传或自动解压 ZIP 的按钮。

三种格式对应不同工程类型；选择一种格式不会自动改写你的源码。插件能否在设备上使用还取决于插件加载环境、设备架构和源码兼容性。IPA 可以无证书编译，但安装时仍需要兼容的巨魔环境或后续签名。

先记住这几个词

仓库 Repository
GitHub 上存放整个项目的文件夹。你的仓库叫 mango6i/iOSForge。
分支 Branch
同一项目的一条开发版本线。本指南都使用默认的 main，先不要改它。
提交 Commit
保存一次源码或配置修改。网页里的 Commit changes 就是确认保存。
工作流 Workflow
告诉云端电脑如何编译的步骤。编译用 build.yml；pages.yml 只负责发布这个网页。
Token / 访问令牌
你给网页调用 GitHub 的授权凭证，不是 GitHub 登录密码。
产物 Artifact
编译完成后保存的结果。GitHub 通常会再套一层 ZIP 压缩包供下载。
STEP 01

先把自己的源码上传到仓库

下面以插件工程放在 plugin 文件夹为例。文件夹名字可以不同，但后面的配置必须与实际名字一致。

  1. 在电脑上解压你的源码。

    打开源码文件夹，确认能找到 Makefile 和代码文件。Theos 插件通常还需要包信息文件 control、过滤配置 .plist 等；具体保留原工程需要的文件。只有一个 .xm 文件通常还不够。

  2. 把完整插件工程整理到一个名为 plugin 的文件夹。

    检查 Makefile 是直接位于 plugin/Makefile，而不是多套了一层 plugin/项目名/Makefile。如果你保留了多层目录，配置路径也要包含那一层。

  3. 打开仓库的 Code 页面，登录 mango6i 账号。

    打开你的项目仓库 ↗。右上角看到 Sign in 表示还没登录。GitHub 登录和工作台里的 Token 是两件事。

  4. 点击 Add file → Upload files。

    把整理好的 plugin 文件夹拖入上传区域，保留里面的目录结构。不要只上传源码 ZIP：当前流程不会替你解压后寻找工程。

  5. 检查列表，然后点击 Commit changes。

    提交说明可以填写“上传插件源码”，分支使用 main。回到文件列表，点开 plugin，应该能看到 Makefile 和代码文件。文件太多或太大时，可用 GitHub Desktop 上传；GitHub 网页上传有大小和数量限制。

完成标志：仓库里能看到你的工程文件，而不只是一个压缩包。下一步要告诉编译工具：工程放在哪里。

STEP 02 · DYLIB / DEB

给插件工程填写配置

如果你要编译 IPA，可以直接看应用工程的配置步骤。编译 dylib 或 deb，继续下面的操作。

  1. 在仓库根目录打开 iosforge.toml。

    “根目录”就是打开仓库后最外面那层，与 README.md 同一层。点击文件右上角的铅笔按钮进入编辑。

  2. 更新已有的项目配置。

    下面是工程放在 plugin 文件夹时的配置。修改已有的 [project] 和 [theos]，不要在文件末尾重复添加同名区块。项目名可以改，路径要与文件夹一致。

iosforge.toml · 插件配置
[project]
name = "MyPlugin"
kind = "tweak"
minimum_ios = "15.0"

[theos]
project_dir = "plugin"

原文件里如果写的是 # project_dir = "plugin"，请去掉开头的 #。带 # 的行只是说明文字，不会生效。路径区分大小写，Plugin 和 plugin 要写一致。

  1. 检查插件 Makefile 的系统目标。

    仓库配置要求 iOS 15.0 起步；Theos 的实际编译目标还需要在工程 Makefile 中设置。将目标系统设为 15.0，并按你的设备和插件环境选择架构。

Makefile · iOS 15 目标
TARGET = iphone:clang:latest:15.0

如果你的项目面向 rootless 插件环境，在工程已有的 Makefile 配置中使用 THEOS_PACKAGE_SCHEME = rootless，放在引入 Theos 规则之前。它是插件安装布局的选择，并不等于“所有 iOS 15+ 设备都可直接安装”。已有项目要同时检查依赖是否适配 rootless。

  1. 点击 Commit changes 保存修改。

    配置里的 project_dir 应当指向包含 Makefile 的目录。例如 Makefile 在 sources/MyPlugin/Makefile，就填写 project_dir = "sources/MyPlugin"。

完成标志：工程路径已经填写并保存，路径下确实有 Makefile。dylib 和 deb 共用这套源码配置。

STEP 03

创建网页需要的 GitHub Token

这个步骤通常在首次使用、令牌到期或权限变化时才需要做。每次重新打开工作台，你仍需要重新粘贴令牌；网页不会替你保存它。

  1. 打开 GitHub 的访问令牌创建页面。

    创建 Fine-grained token ↗。如果要求登录或验证身份，按 GitHub 提示操作。也可以从头像 → Settings → Developer settings → Personal access tokens → Fine-grained tokens → Generate new token 进入。

  2. 按下面这张表填写。

    网页只需要启动构建和读取结果，所以只授权你要使用的仓库以及 Actions 权限即可。

GitHub 页面上的选项填写或选择什么
Token name填写 iOSForge 网页构建，便于以后辨认。
Expiration选择有效期，例如 30 天。到期后需要换新令牌。
Resource owner选择仓库所属账号 mango6i。
Repository access选择 Only select repositories，然后选中 iOSForge。
Repository permissions → Actions设为 Read and write（读取和写入）。只有 Read 不能发起构建。
Metadata如果自动出现只读权限，保持默认。无需给本网页添加管理仓库或修改源码的权限。
  1. 点击 Generate token，复制生成的令牌。

    它是一长串字符。请自己保管，别提交到公开仓库、发到评论或截图里。如果遗失，可以删除旧令牌再生成新的。

  2. 回到编译工作台，粘贴到 GitHub Token 输入框。

    默认显示为圆点；右侧的眼睛按钮可以临时显示或隐藏。不要把 GitHub 登录密码填进去。

为什么我登录 GitHub 了，网页还要 Token？

GitHub 的登录状态不会自动授权这个独立网页调用编译接口。上传文件用 GitHub 登录；在本网页发起构建用 Token。令牌会从浏览器直接发给 GitHub，仅保留在当前页面内存中。

权限步骤参考 GitHub 访问令牌说明 ↗ 与 手动构建接口权限 ↗。

STEP 04

回到工作台，开始第一次构建

  1. 点击左侧第一项“编译工作台”。

    选择 .dylib 或 .deb。如果要做应用，先完成第七节 IPA 准备再选择 .ipa。

  2. 检查仓库和分支。

    GitHub 仓库填写 mango6i/iOSForge，分支填写 main。要使用其他仓库，该仓库也必须包含对应的 iOSForge 工具与 .github/workflows/build.yml 编译流程。

  3. 填入 Token，点击“开始构建”。

    看到“已提交”或“排队中”说明请求已发送。构建期间按钮会暂时不可点，避免重复提交。保留这个页面以持续查看进度。

  4. 观察右侧的三个步骤。

    “提交任务”表示 GitHub 接收请求；“云端编译”表示处理源码；“获取产物”表示读取本次输出文件。首次准备环境可能较慢，等待时间取决于排队、依赖和工程大小。

等待时不用一直点“开始构建”。

同一分支的新构建可能取消前一个任务。超过约 30 分钟，网页会暂停自动刷新并提示你打开日志；这并不代表网页替你取消了云端任务。

不用 Token，也能手动操作吗？

可以。登录 GitHub 后，进入仓库 Actions → GitHub Actions → Run workflow，选择 main，再选 dylib、deb 或 ipa 后运行。这是在 GitHub 内操作，因此不需要把 Token 填到本网页。

注意选择编译流程：Publish iOSForge Web 是发布网页，不会帮你编译插件或应用。

STEP 05

成功之后，去哪里下载？

  1. 等右侧显示“已完成”。

    正常情况下，“构建产物”区域会出现文件名、大小和“下载 ZIP”按钮。点击按钮，保存到电脑。

  2. 解压下载的 ZIP。

    里面才是你选择的 .dylib、.deb 或 .ipa 文件。下载文件带 ZIP 后缀是正常的，不要把 ZIP 直接改名成 IPA。

  3. 如果网页下载失败，点击“在 GitHub 查看日志”。

    登录 GitHub，在这次运行的总结页找到 Artifacts 区域，点击产物名称下载。浏览器跨站下载限制、令牌到期或产物已过期，都可能影响网页下载。

关闭网页不会直接停止 GitHub 上的任务。但重新打开页面后，当前版本不会自动恢复上一次任务和 Token；可以去仓库的 Actions 历史中找到那次运行。

完成标志：你已解压拿到对应格式的文件。构建成功只表示编译流程通过，后续仍应在目标设备和正确的安装环境中验证。

APP BUILD · IPA

如果你要编译的是 IPA

IPA 是 iOS 应用的安装包。它需要一个可编译的 Xcode 应用工程。插件源码不能仅靠切换选项变成应用。

  1. 上传完整 Xcode 项目。

    保留 .xcodeproj 或 .xcworkspace 目录、应用代码、资源和项目依赖文件。它们在文件系统里是目录，不要解散里面的文件。若原项目使用 workspace，就填写 workspace 路径。

  2. 确认 Scheme 已共享。

    Scheme 是 Xcode 中的一套构建方案。在 Xcode 的 Product → Scheme → Manage Schemes 中查看名称并勾选 Shared，再把对应修改提交。拿到别人的源码时，先确认对方提供的 Scheme 名字。

  3. 填写应用的项目配置。

    下面假设工程在仓库最外层，叫 MyApp.xcodeproj，Scheme 叫 MyApp。请换成真实名字。如果同一仓库还要编译插件，用 kind = "hybrid" 并保留完整的 [theos] 配置。

iosforge.toml · 应用配置
[project]
name = "MyApp"
kind = "app"
minimum_ios = "15.0"

[app]
project = "MyApp.xcodeproj"
scheme = "MyApp"
configuration = "Release"
  1. 选择编译模式：巨魔或后续自签，保持默认“无证书编译”。

    这个模式不需要 Apple 开发者证书、不需要 Provisioning Profile（描述文件），也不需要 ExportOptions.plist。云端关闭 Xcode 的代码签名，将编译出的应用放进 Payload 文件夹，再打包成 MyApp-unsigned.ipa。文件名中的 unsigned 表示“未签名”，不是编译失败。

  2. 回到工作台，选择 .ipa，填入工程路径和 Scheme。

    编译模式保持“无证书编译”，检查仓库与分支，再填 GitHub Token，点击“开始构建”。这里的 GitHub Token 只是触发云端任务的凭证，与 Apple 证书是两回事。

输入框示例怎么确认
Xcode 工程路径MyApp.xcodeproj从仓库最外层开始写；放在 app 里就是 app/MyApp.xcodeproj。
SchemeMyApp填写 Xcode 中已共享的方案名，不是随便起的名字。
IPA 编译模式无证书编译巨魔或后续自签选这一项；在 GitHub 的 Run workflow 中对应 ipa_signing = unsigned。
导出配置文件无证书模式不需要仅切换到“证书导出”时才显示，需要填写真实的 ExportOptions.plist 路径。

完成这些准备后，再点击“开始构建”。应用归档会使用项目配置里的最低系统版本，默认 iOS 15.0。源码或第三方依赖使用了更高系统才有的能力时，仍需在代码中处理兼容性。

下载后怎么安装？按你的设备选一条路

  1. 先解压 GitHub 下载的 ZIP。

    找到里面的 MyApp-unsigned.ipa，然后把这个 IPA 传到手机。不需要再把 IPA 本身解压，也不要把外层 ZIP 改成 IPA 后缀。

  2. 已经安装巨魔（TrollStore）的用户。

    在手机上使用“共享 → TrollStore”打开 IPA，或者进入 TrollStore，点击添加按钮选择该文件，再确认安装。具体入口以你安装的版本为准。请只安装自己拥有或获授权的应用。

  3. 准备自己签名的用户。

    把这个 IPA 导入你使用的签名工具，按该工具要求提供自己的 Apple 账号或签名证书与描述文件，完成签名后再安装。自签仍受账号权限、设备授权和有效期限制；编译无证书不等于安装也无需签名。

iOS 15+ 编译支持，不等于所有 iOS 15+ 都支持巨魔。

巨魔对系统版本、设备和安装方法有自己的要求，请以 TrollStore 官方说明 ↗为准。本工具不会安装巨魔、绕过设备的安装限制，也不保证任意 IPA 都能运行。

依赖特殊 entitlements（应用权限声明）的项目，需要按原项目要求单独处理。无证书打包不会自动把 Xcode 的权限文件写进可执行文件，也不会替你添加私有权限；后续签名工具能授予的权限同样有限。

什么时候才选择“证书导出”？

只有你希望云端直接导出带 Apple 签名的 IPA，并已准备好匹配应用、团队和分发方式的证书、描述文件与导出配置时，才切换到这一项（GitHub 参数为 signed）。当前通用流程不会自动创建或导入证书；需要按你的项目补充依赖安装、证书导入和描述文件安装步骤。证书凭证保存在仓库 Settings → Secrets and variables → Actions，不要上传到公开源码中。具体配置见 GitHub 的 Apple 签名指南 ↗。

完成标志：你已拿到未签名 IPA，并知道自己接下来用巨魔安装，还是交给签名工具处理。设备运行效果还需实际验证。

TROUBLESHOOTING

遇到问题，先看这里

找不到 Run workflow，或者看不到上传按钮

先看 GitHub 页面右上角。如果显示 Sign in，请登录拥有仓库权限的账号。再确认自己打开的是编译流程，而不是单个历史运行页。访问公开仓库不等于已经登录。

401：访问令牌无效或过期

去 GitHub 查看令牌是否过期或被删除。重新复制有效令牌，清空工作台里的旧内容再粘贴。不要填写账号密码，也不要多带空格或换行。

403：没有权限，或请求额度用完

检查令牌是否选中了 iOSForge 仓库，Actions 是否为 Read and write。组织仓库还可能需要管理员批准。如果 GitHub 提示 API 请求额度耗尽，等额度恢复后再试。

404：找不到仓库或工作流

确认仓库写成 mango6i/iOSForge，main 分支中存在 .github/workflows/build.yml。私有仓库授权不正确时也可能返回 404。请检查令牌授权的账号和仓库。

提示未配置 Theos 工程，或找不到 Makefile

打开 iosforge.toml，确认 project_dir 这一行没有以 # 开头。然后按路径点进仓库文件夹，检查 Makefile 是否就在那一层、大小写是否一致。只上传一个 ZIP 不能通过这项检查。

提示找不到头文件、库，或出现 clang / linker 错误

打开运行日志，找到第一个实际编译错误。它通常表示项目依赖缺失、代码不兼容或目标架构不匹配。保留出错文件名和前后几行信息，结合原项目的依赖说明处理。切换网页主题或重新填写 Token 不会修复源码错误。

IPA 提示 No signing certificate / No profiles

如果你要给巨魔或自签工具使用，确认选择了“无证书编译”，GitHub 参数为 ipa_signing = unsigned；不需要填写导出配置。如果仍出现签名错误，检查项目自定义脚本是否额外调用 codesign 或签名服务。若选择的是“证书导出”，则需要检查证书、描述文件、团队和 Bundle ID 是否匹配，并确保在本次云端环境中导入。仅上传 ExportOptions.plist 不会安装证书。

拿到 unsigned.ipa 后，为什么点一下不能直接安装？

unsigned 表示没有 Apple 签名，不是万能免签安装包。兼容且已经安装巨魔的设备可交给 TrollStore 处理；其他用户需要先在自己的签名工具里签名。特殊权限、应用扩展、系统版本与依赖也可能影响安装或启动，详见第七节。

已经成功了，为什么没有文件？

确认运行的是 GitHub Actions 编译流程。没有配置插件源码时，自动推送触发的检查可能成功跳过编译，所以没有产物；Publish iOSForge Web 的成功也不表示插件编译成功。手动选择正确产物后再运行，并查看该次日志。

修改源码后，为什么没有自动编译？

当前自动触发设置只覆盖部分工具和配置路径，不覆盖任意源码目录。保存源码后，可以回本网页点击开始构建。如果需要“每次修改自己的源码都自动编译”，要把实际源码目录加入 build.yml 的 push 路径规则。

页面一直排队、显示刷新中断，或者下载按钮没反应

先点右侧 GitHub 日志链接，确认任务是否仍在运行。排队取决于 GitHub 的可用环境；刷新中断可能是网络问题。不要连续提交同一分支的新任务。文件下载失败时，可在 GitHub 运行总结页的 Artifacts 区域下载。

第二次使用，就简单了

项目和签名环境配置好后，日常操作就是：

  1. 把修改后的源码保存到同一个仓库、同一个分支。

暂时没有源码时，可以先保存这个网站。之后也可以把完整源码压缩包交给协作助手，让助手协助上传和配置；这属于对话协助，并不是网页内的上传功能。
